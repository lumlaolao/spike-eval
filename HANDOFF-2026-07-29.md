## 3. Open problems, most important first

### 3a. The suite is too small to rank models
15 discriminating positions; 9 of 25 are free (every model solves). Need roughly
60-100 discriminating positions for a separable 7-model leaderboard. That is
2-3 more mining rounds.

### 3b. My mining optimisation BACKFIRED — fix the guidance before mining again
`CLAUDE.md` currently says *"the ONLY band that yields quotable positions is
n_options 3..4"*. **That is wrong and it is still in the repo.** Measured:

    verification yield by option count (overnight-2, random sample)
      n=2 -> 0.139   n=3 -> 0.055   n=4 -> 0.073   n>=5 -> ~0.05

    overnight-2 (random sample):  300 sampled -> 32 verified (10.7%)
    overnight-3 (3-4 band only):  320 sampled ->  6 verified (1.9%)

I optimised for "fraction of verified keys that survive the suite filters" and
never measured "fraction of attempted positions that verify at all". Those pull
opposite ways: n=2 has ~0% suite survival but the best verification rate.
**Random sampling beat the targeting ~2x on usable keys while spending less
compute per position.** Next round: revert to random sampling across all option
counts, and score 2-option positions against an explicit 0.5 floor instead of
excluding them.

### 3c. No Forge object IDs anywhere (user-spotted)
Zero `getId()` / `getUniqueNumber()` calls in the overlay. Cards reach the prompt
by NAME only, so two copies of one card in a menu are indistinguishable:

    1) CAST Wasteland [{T}, Sacrifice CARDNAME: ...]
    2) CAST Wasteland [{T}, Sacrifice CARDNAME: ...]

2 of puz-v1's 25 positions look like this. Both score [0,0], so the suite is
sound **by luck**. A guard is now in `select_suite.indistinguishable_answer()`
(always-on) that drops any position where identical text scores differently.

**The real fix is upstream and not done:** emit a per-card disambiguator when a
name repeats within one menu. It is a DATA change (the menu is baked into
`row["prompt"]` by the game, not by `prompt_contract`), so `contract_sha` is
untouched and old artifacts stay comparable. Needs a Java change — do it while
no games are running.

Wider consequence: without ids the model also cannot say *which* creature to
target/block when two share a name, nor refer to a permanent across turns. That
is a play-quality limit, not just a scoring one.

### 3d. Missing from the roster
**gpt-5 was never scored** (~$26 at observed rates). Deliberately held for a
suite that can rank. The key is uncapped now, so it is affordable whenever.

### 3e. puzzle_run has no truncation-retry ladder
The Java bridge already does `finish_reason=length -> retry at 2x tokens`
(visible in `runs/record.log`). `puzzle_run` just records an interface failure.
That asymmetry caused the day's worst measurement error: kimi-k3 scored 0.600
with 33% interface failures at 4k tokens, and 0.720 with 8% at 16k. **Porting
the ladder removes per-model token guessing entirely.** Highest-value cheap fix.

## 4. AWS — verdict and how to redo it

**Cost is not the obstacle.** The rollout confirm pass is ~66 CPU-hours; on 32
vCPU that is ~2.1h = **~$0.85 spot / ~$3.10 on-demand**, versus 7.5h locally.

Measured: full Forge builds from bare metal in **~90s** at the pinned SHA, and
cloning by SHA is *more* reproducible than the local checkout. My earlier claim
that shipping Forge was too awkward and drift-prone was wrong.

**Four porting bugs, all fixed in `~/.claude/jobs/b5e85896/tmp/userdata5.sh`:**
1. macOS AppleDouble `._*.java` files break checkstyle — use
   `COPYFILE_DISABLE=1 tar --exclude '._*'`
2. `mvn compile` is not enough — **`install`** is required, or `build-classpath`
   cannot resolve sibling SNAPSHOT jars (gave a 1232-byte classpath vs local
   10693 / 103 jars)
3. the launcher's `CP` starts with a RELATIVE `target/classes` — must run from
   `forge-gui-desktop/`, not Forge root
4. EC2 serial console does not populate for short-lived instances — **results
   need S3 via an IAM role**, not console output

**Other constraints:** vCPU quota is 32 in both us-east-1/us-east-2 (raise
`L-1216C47A` / `L-34B43A08` to go bigger — the G/VT GPU quota that got approved
is useless here). Spot capacity was refused across 5 instance types x 3 AZs all
afternoon; plan on-demand.

**Recommendation:** worth doing, but bake an AMI with Forge pre-built at the
pinned SHA + an IAM role for S3 results. Then each mining round is ~2h and ~$1
instead of a night.
