## Phase 1b: coherence between decisions (owner, 2026-10-16)

Research question (owner): is a fresh prompt per decision the right way to handle the many decisions of a
Magic game, or would one long conversation, as Claude Code and mage-bench run, be better? What was found:
- the count is already the real decisions: 35-50 asked per Luna game, while the harness passes 88-142
  windows with nothing usable or a spot already passed, the same filtering MTG Arena's auto-pass and
  stops do for people;
- the evidence favours a fresh, engine-rendered state per decision for a game: models are about 39%
  worse in multi-turn conversations than single-turn (Laban et al., ICLR 2026), reliability falls as the
  input grows (Chroma, context rot), and a 2026 Slay the Spire testbed (AgenticSTS) assembles each
  decision from slots, not a transcript. Anthropic's context-engineering guide names compaction, notes
  and just-in-time lookup, which the seat already has;
- what fresh-per-decision costs: the model's reasoning does not carry from one decision to the next, so
  a multi-step line (ritual, ritual, tutor, cast) is re-derived at each step. Inside one decision it does
  carry (the assistant message with `reasoning_details` goes back with each tool round, as OpenRouter's
  reasoning guide asks).
